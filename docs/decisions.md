# Decisions

Which libraries Zenith Vault uses, and the patterns every package follows. The security invariants these decisions
keep are in [threat-model.md](threat-model.md); the IDs below refer to it.

The balance: a dependency is taken where writing the code ourselves would be maintenance without a security or
protocol reason, and refused where the exact rule is the point (the NIP text, the Durable Object limits, the logging
invariant). `packages/core` depends on `@noble` only (EV-7).

## Libraries

Status is _In use_ when the code uses it, _Planned_ when it is decided and lands with the revision of OPS-3 and SUP-1
that allows it.

| Area                                                       | Candidates                        | Decision                                    | Status  | Reason                                                                                                                                                                        |
| ---------------------------------------------------------- | --------------------------------- | ------------------------------------------- | ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Routing of the relay Worker and the Blossom Worker         | Hono, itty-router, plain `fetch`  | Hono, in both Workers                       | Planned | Routes, CORS and JSON responses are common code; one router for both Workers, never one each. The exact admin URL (OPS-1) and not waking the DO for public HTTP (RES-3) stay. |
| Input validation in the relay                              | Valibot, Zod, own code            | Valibot                                     | Planned | Admin commands, the allowlist backup, the manifest and the Worker's variables are plain schemas; one function turns a Valibot result into a code of a closed set.             |
| Input validation in core                                   | Valibot, Zod, own code            | Own code                                    | In use  | Each check maps to a NIP rule and a rejection code, and core depends on `@noble` only (EV-7).                                                                                 |
| Nostr events, filters, NIP-42, NIP-98, the reference model | nostr-tools and others            | Own code; nostr-tools in tests only         | In use  | The NIP text is the rule (seven escapes only, empty lists match nothing); nostr-tools' `verifyEvent` caches its result on the object (nostr-tools#561, EV-7).                 |
| SQL building                                               | sql-template-tag, Kysely, Drizzle | Own `sql` tag (`packages/relay/src/sql.ts`) | In use  | Queries are split at 90 bound parameters, under the Durable Object's limit of 100, and RES-2's source analysis reads every `exec` argument.                                   |
| Migrations                                                 | Drizzle                           | Own (`packages/relay/src/schema.ts`)        | In use  | A few statements applied in the DO's own transaction when the store opens; no generator is needed.                                                                            |
| Blossom client or server SDK                               | Existing Blossom SDKs             | Own code                                    | Planned | The SDKs do not run on Workers.                                                                                                                                               |
| base64                                                     | Own decoder, `atob`               | `atob`, after an exact-form check           | In use  | Workers and Node 24 both have it; the check stays because `atob` skips whitespace.                                                                                            |
| Hex                                                        | Own code, `@noble/hashes`         | `bytesToHex` of `@noble/hashes`             | In use  | Already a dependency of core, which exports it.                                                                                                                               |
| UTF-8 byte length                                          | `TextEncoder`, own code           | Own `utf8ByteLength`                        | In use  | It counts without copying the text, so an oversized message is refused before it is encoded (RES-1).                                                                          |
| JSONC of the deployment files                              | Own parser, jsonc-parser          | jsonc-parser, as a dev dependency           | Planned | The deployment script reads JSONC as wrangler does; a maintained parser replaces the hand-written one.                                                                        |
| Command-line arguments of the deployment script            | `node:util` `parseArgs`, own      | Own `splitArgs`                             | In use  | Unknown options pass through to wrangler, which `parseArgs` does not do without listing them all.                                                                             |
| Logging                                                    | Logging libraries                 | Own `logEvent`                              | In use  | A log line carries an event name and fields from closed sets only (DATA-1).                                                                                                   |

## Patterns

| Concern                 | Pattern                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Results                 | In the relay's internal results (configuration, allowlist, store, backup): a discriminated union, `{ ok: true, ... }` or `{ ok: false, code }`, the code from a closed set. Exceptions: core's protocol rejections carry `error` with the NIP prefix; `parseJsonText` fails without a code and `parseRelayUrl` answers `undefined`, since each has one way to fail; HTTP answers carry `reason`. Scripts are command-line tools and throw instead. |
| Closed sets             | An `as const` array, the union derived from it, and a `Set` of it for checks at run time. Per-member handling is a `Record<Union, ...>` table, so a missing member does not compile.                                                                                                                                                                                                                                                               |
| Protocol messages       | The NIP prefix and the readable message are added where the response is built: `vault.ts` for WebSocket messages, `admin.ts` for the admin route. Core's event, filter, message and AUTH rejections still carry their prefix and message, with limits in the text.                                                                                                                                                                                 |
| Shared checks           | `packages/core/src/encoding.ts`: `bytesToHex`, `isHex32` (64 lowercase hex characters), `isRecord`, `decodeUtf8Strict`, `parseJsonText` and `decodeBase64`, used by core and the relay instead of local copies.                                                                                                                                                                                                                                    |
| Configuration           | `parseXConfig(env)` returns a result with a closed set of codes. The checks of a variable live once (`packages/relay/src/vars.ts`) and serve both the Worker and the deployment script, so a deployed value is one the Worker accepts. The Blossom Worker (planned) will do the same.                                                                                                                                                              |
| Capabilities and brands | A capability such as SQL lives in a `#` field behind one entry point. A value that passed a check has its own type (`VerifiedEvent`, `VaultConfig`, `AuthorizedCommand`), made in one place. What a type cannot express is pinned by source analysis.                                                                                                                                                                                              |
| Logging                 | `logEvent(event, fields)` with fields from closed sets (DATA-1); the Blossom Worker (planned) will use the same shape.                                                                                                                                                                                                                                                                                                                             |
| SQL                     | The `sql` tag binds every value; only `EventStore#run` executes it (RES-2).                                                                                                                                                                                                                                                                                                                                                                        |
